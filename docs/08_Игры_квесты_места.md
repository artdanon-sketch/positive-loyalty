# POSitive Loyalty — игры, квесты, места Пхукета

Версия 1.0 · для Claude Code · приоритет: после срезов 1–5 и партнёрств

---

## 1. Зачем это в программе лояльности

Три задачи, каждая своя:

- **Игры** — удержать внимание, когда гость едет в тук-туке без интернета. Это причина открыть приложение не в момент оплаты, а просто так. Каждое такое открытие — шанс показать акцию рядом.
- **Квесты** — превратить сеть заведений в маршрут. Гость проходит цепочку точек и получает награду. Для заведений это трафик от соседей, для нас — самый наглядный аргумент «одна карта на весь остров».
- **Места** — дать туристу причину доверять приложению как гиду, а не только как кошельку. Курируемый список смотровых, пляжей и рынков с заведениями сети рядом.

Одна оговорка сразу, и она принципиальная: **игры не дают баллов.** Баллы это деньги, а офлайн-игра, результат которой считается на клиенте, — это бесконечный источник фальшивых результатов. Игры дают значки, места в рейтинге и билеты в еженедельный розыгрыш. Розыгрыш проводит сервер, приз финансирует заведение-спонсор. Деньги остаются под контролем ledger.

## 2. Игры

### Принципы

- Работают полностью офлайн: логика, ассеты и результаты кэшируются в PWA через Service Worker и IndexedDB. При появлении сети результаты синхронизируются.
- Каждая игра — до 60 секунд на партию. Это заполнение паузы, не хобби.
- Брендинг заведений внутри игр — это и есть реклама: карточки в «Найди пару» — логотипы заведений сети рядом с гостем.
- Никакого текста, требующего перевода, внутри игрового поля. Только цифры и картинки — четыре языка не разъедутся.

### Три игры на старт

| Игра | Механика | Что рекламирует |
|---|---|---|
| **Найди пару** | Классическая memory на 12–16 карточках с логотипами заведений сети в радиусе 3 км | Заведения рядом: гость запоминает логотипы, не замечая этого |
| **Точно в цель** | Остановить бегущую полоску в зелёной зоне; серия попаданий — комбо | Ничего явно; чистое удержание внимания |
| **Что где** | Показываем фото блюда или места — угадать, в каком заведении сети это подают или где это | Знакомит с меню партнёров |

Все три — одна архитектура: `GameSession {gameId, guestId, startedAt, score, seed, clientHash}`. `seed` выдаётся сервером при наличии сети и кэшируется пачкой на 20 партий вперёд, чтобы офлайн-игры оставались детерминированными и проверяемыми.

### Награды без денег

```
Значки       — «10 партий», «Идеальная память», «Неделя подряд». Хранятся у гостя, видны в профиле
Рейтинг      — недельный, среди гостей одного заведения (не всей сети — слишком анонимно)
Билеты       — 1 билет за партию с результатом выше медианы, максимум 3 в день
Розыгрыш     — раз в неделю сервер выбирает победителя среди билетов; приз — OfferGrant от спонсора
```

Спонсор розыгрыша — заведение, которое включило это в настройках и указало приз («ужин на двоих»). Это ещё одна бесплатная для нас точка монетизации внимания гостя в пользу заведения.

### Антифрод

Игры не дают денег, поэтому глубокая защита не нужна. Достаточно: серверная валидация правдоподобности результата (партия «Найди пару» за 0,8 секунды — отклоняется), лимит билетов в день, один аккаунт — один розыгрыш. Всё остальное — не наша проблема, потому что ставки копеечные.

## 3. Квесты

### Что это архитектурно

Квест — **многозвенное партнёрство** с последовательностью. Реиспользуем PartnershipTerm: каждая точка квеста — Term с триггером `ON_VISIT`, а завершение цепочки — событие `quest.completed`, по которому выдаётся финальная награда.

```prisma
model Quest {
  id            String   @id @default(uuid())
  ownerTenantId String?                        // кто создал: тенант или платформа (null)
  title         Json                           // i18n
  description   Json                           // i18n
  coverUrl      String?
  status        QuestStatus                    // DRAFT | ACTIVE | ENDED
  startsAt      DateTime?
  endsAt        DateTime?
  ordered       Boolean  @default(false)       // строго по порядку или в любом
  steps         QuestStep[]
  finalReward   Json                           // PartnershipReward от спонсора
  rewardTenantId String                        // кто даёт финальную награду
  maxCompletions Int?
}

model QuestStep {
  id         String  @id @default(uuid())
  questId    String
  order      Int
  kind       StepKind                          // VISIT_VENUE | CHECKIN_PLACE | ANSWER_QUESTION
  tenantId   String?                           // для VISIT_VENUE
  placeId    String?                           // для CHECKIN_PLACE
  question   Json?                             // для ANSWER_QUESTION, i18n + варианты
  hint       Json                              // i18n подсказка
  stepReward Json?                             // опционально маленькая награда за шаг
}

model QuestProgress {
  guestId     String
  questId     String
  completedSteps Json                          // [stepId, …] с временем
  completedAt DateTime?
  @@id([guestId, questId])
}
```

### Как засчитывается шаг

- `VISIT_VENUE` — по факту начисления в этом заведении (событие `ledger.earned`). Не по геолокации: геолокацию подделать легче, чем оплатить чек.
- `CHECKIN_PLACE` — QR-табличка на месте (смотровая, пляж). Подписанный QR с местом и ротацией ключа раз в неделю. Плюс проверка геолокации как второго фактора: если телефон утверждает, что он на Промтеп, а GPS показывает Патонг — шаг не засчитан.
- `ANSWER_QUESTION` — ответ на вопрос о месте; правильный ответ проверяет сервер.

### Кто создаёт квесты

Два источника. **Платформа** — курируемые квесты по острову: «Три пляжа Ката», «Старый город за день». **Заведения** — через партнёрства: пять кафе одного района договариваются о квесте «Кофейная миля», финальный приз — от одного из них или общий ваучер.

Для тенантов конструктор квеста — расширение конструктора партнёрств: выбрать участников из активных партнёров, порядок, финальную награду. Каждый участник подтверждает участие — тот же механизм принятия Term.

### Гостевой интерфейс

Вкладка «Квесты» внутри раздела «Рядом». Карточка квеста: обложка, число шагов, награда, «3 из 5 пройдено». Внутри — карта с точками, пройденные отмечены. Офлайн доступны описание, подсказки и карта пройденного; проверка шага требует сети или уходит в очередь.

## 4. Места

### Что это

Курируемый справочник интересных мест Пхукета — не заведений, а мест: смотровые, пляжи, храмы, рынки, закаты. С фото, коротким текстом на четырёх языках, часами, советом «когда лучше» и — главное — **заведениями сети в радиусе 500 метров**.

```prisma
model Place {
  id          String   @id @default(uuid())
  slug        String   @unique
  title       Json                             // i18n
  summary     Json                             // i18n, до 300 символов
  category    PlaceCategory                    // VIEWPOINT | BEACH | TEMPLE | MARKET | NATURE | CULTURE
  lat         Float
  lng         Float
  photos      String[]
  bestTime    Json?                            // i18n «на закате»
  tips        Json?                            // i18n
  qrSecret    String?                          // для чек-ина в квестах
  isPublished Boolean  @default(false)
  curatedBy   String                           // платформа
}
```

Контент создаёт платформа, тенанты не редактируют. Это единственное место в продукте, где мы выступаем как редакция, и это осознанно: качество справочника — часть доверия к приложению.

### Офлайн

Список мест, тексты и превью фото — в кэше PWA после первого открытия. Тайлы карты — предзагруженный набор для острова на зуме 11–14 через собственный тайл-сервер или лицензированного провайдера с офлайн-правами. `[гипотеза: объём около 40–60 МБ, проверить]`. Это делает раздел полезным именно там, где сети нет — на серпантине к смотровой.

### Связь с сетью

У каждого места — блок «Рядом из сети Positive»: заведения в 500 метрах с их актуальными акциями. Турист смотрит закат на Промтеп и видит, что в трёхстах метрах кафе даёт кэшбэк 10%. Это и есть точка, где справочник превращается в трафик.

## 5. Приоритет и порядок

| Что | Когда | Почему |
|---|---|---|
| Места (справочник, офлайн) | после срезов 1–5 | Дёшево, полезно сразу, не требует новых механик |
| Игра «Найди пару» | вместе с местами | Одна игра для проверки гипотезы удержания. Не три |
| Квесты платформенные | после партнёрств | Требуют PartnershipTerm и чек-ины |
| Квесты тенантов | v3 | Требуют зрелых партнёрств |
| Розыгрыши со спонсором | v3 | Требуют юридической проверки — розыгрыш в Таиланде может считаться лотереей `[проверить с юристом]` |
| Остальные игры | по данным первой | Если «Найди пару» открывают — добавляем. Нет — не тратим время |

**Метрика гипотезы:** доля гостей, открывших приложение вне момента оплаты хотя бы раз в неделю. Если игра и места её не двигают — это не наш продукт, и мы это узнаем за месяц, а не за полгода.

---

## 6. Что не делаем

- Не делаем игры с реальными призами в баллах. Никогда.
- Не делаем мультиплеер и социальные функции внутри игр. Это другой продукт.
- Не делаем пользовательский контент в местах (свои отзывы, свои фото). Модерация дороже пользы на нашем масштабе.
- Не строим свою карту с нуля. Тайлы — лицензированные.
- Не запускаем розыгрыши до юридического заключения по лотерейному законодательству Таиланда.
