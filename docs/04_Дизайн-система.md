# POSitive Loyalty — дизайн-система

Версия 1.0 · для Claude Code
Источник: прототипы `Прототип — бэк-офис ресторана.html`, `Прототип — приложение владельца.html`, `Прототип — гостевое приложение v2.html`.

---

## 1. Принцип

Одна система на три поверхности: бэк-офис, приложение владельца и кассира, гостевое приложение. Отличаются плотностью и размером целей нажатия, но не языком.

Все токены живут в `packages/ui/tokens.css` как CSS-переменные. React-компоненты не содержат hex-значений — только переменные. Это единственный способ, при котором тёмная и светлая темы не разъедутся через месяц.

---

## 2. Цвет

### Тёмная тема — основная

```css
:root {
  /* поверхности */
  --bg:      #0A0E14;
  --surf:    #131922;
  --surf-2:  #1A222E;
  --surf-3:  #212B39;
  --line:    #232D3C;
  --line-2:  #2E3A4B;

  /* текст */
  --tx:      #EDF2F8;
  --tx-2:    #93A0B2;
  --tx-3:    #5F6B7C;

  /* бренд */
  --mint:    #34E1B4;
  --cyan:    #22D3EE;
  --amber:   #FFB84D;
  --coral:   #FF7A6B;
  --violet:  #A78BFA;
  --grad:    linear-gradient(135deg, #34E1B4, #22D3EE);

  /* статусы */
  --good:    #3FD69C;
  --warn:    #FFB84D;
  --bad:     #E8837A;
}
```

### Светлая тема

Не инверсия. Отдельно подобранные поверхности и тени.

```css
[data-theme="light"] {
  --bg:     #EEF1F6;
  --surf:   #F5F8FB;
  --surf-2: #E9EEF5;
  --surf-3: #DDE4EE;
  --line:   #DFE5EE;
  --tx:     #0D131C;
  --tx-2:   #4E5A6C;
  --tx-3:   #8592A4;
  --good:   #199E70;
  --bad:    #D9564A;
}
```

Переключение — атрибут `data-theme` на `<html>`, значение из localStorage, дефолт из `prefers-color-scheme`. Переход плавный: `transition: background .45s, color .45s` на `body`.

### Цвета для графиков — отдельная палитра, не бренд

Бренд-мята слишком светлая для меток данных на тёмном фоне. Для графиков используем валидированный набор:

```css
--s1: #199E70;   /* серия 1 */
--s2: #9085E9;   /* серия 2 */
--s3: #C98500;   /* серия 3 */
```

Набор прогнан через валидатор: попадает в диапазон светлоты для тёмной поверхности, различим при дальтонизме (ΔE 17,3 deutan), контраст к фону выше 3:1. **Не менять на глаз.** Если понадобится четвёртая серия — сначала прогнать через валидацию, а лучше свернуть в «Прочее».

Зелёный и красный для прибыли и убытка допустимы только вместе со вторичным кодированием: положение относительно нуля плюс знак в подписи. Цветом одним — нельзя.

Текст графиков всегда в текстовых токенах, никогда в цвете серии.

## 3. Типографика

Системный стек, без веб-шрифтов: они добавляют задержку, а гостевое приложение должно открываться за две секунды на слабом 4G.

```css
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Roboto, Inter, sans-serif;
```

| Роль | Размер | Насыщенность | Трекинг |
|---|---|---|---|
| Заголовок экрана | 23–30 | 750 | −0,035em |
| Заголовок карточки | 15–16 | 700 | −0,015em |
| Основной текст | 14–15 | 400–450 | 0 |
| Вторичный | 12,5–13 | 400 | 0 |
| Метка секции | 10,5–11,5 | 750 | +0,1em, uppercase |
| Крупное число | 27–43 | 800 | −0,04em |

Все числа — `font-variant-numeric: tabular-nums`. Без этого суммы прыгают при обновлении и таблицы выглядят сломанными.

**Тайский и китайский.** Минимальный кегль для `th` и `zh` на 1 пункт больше латиницы, межстрочный интервал 1,6 вместо 1,45. Тайское письмо не разделяется пробелами — переносы задаются `word-break: break-word` и библиотекой сегментации, если появятся проблемы.

## 4. Форма и пространство

Скругления: 10–12 маленькие элементы, 14–18 карточки, 20–26 крупные блоки, 99px пилюли.

Отступы кратны 4. Внутри карточек 15–20, между карточками 10–14, между секциями 18–22.

Тени только на поднятых поверхностях: модалки, шторки, плавающие кнопки. Карточки в списке отделяются рамкой `--line`, а не тенью — иначе список превращается в кашу.

## 5. Движение

```css
--spring: cubic-bezier(.34, 1.5, .64, 1);
--ease:   cubic-bezier(.22, .61, .36, 1);
```

| Что | Как |
|---|---|
| Переход экрана | opacity .32s ease + translateY(12px) scale(.99) .42s |
| Появление карточек | каскад по 52 мс, translateY(16px) → 0 |
| Нажатие кнопки | scale(.97) на .3s spring |
| Нажатие карточки | scale(.978) + подсветка рамки |
| Индикатор вкладки | transform .45s spring |
| Шторка снизу | translateY(101%) → 0, .55s spring |
| Модальное окно | scale(.94) → 1 + opacity, .5s spring |
| Счётчик числа | 900 мс, easing 1−(1−k)³ |
| Полоса прогресса | width .9s ease |
| Столбцы графика | height .55–.8s ease, каскад по 45–55 мс |

**Уважать `prefers-reduced-motion`:** при включённом — все анимации до 0,01 с, каскады отключаются. Это не опция, а требование доступности.

## 6. Компоненты

Что должно оказаться в `packages/ui`. Каждый — с историей в Storybook и снимком в обеих темах.

**Основа:** `Button` (primary/ghost/danger, sm/md/lg, loading, iconOnly) · `Card` · `Tile` (метрика: k/v/d/badge) · `Chip` (фильтр, toggle) · `Toggle` · `Segmented` · `Input` `Select` `Textarea` `Slider` (с подписями min/max) · `Table` (сортировка, курсорная пагинация, пустое состояние) · `Sheet` · `Modal` (шаги) · `Toast` · `Badge` · `Avatar` · `Skeleton` · `EmptyState` · `Tabs` · `Radio`.

**Доменные:** `MetricTile` · `StackedBarChart` · `HourlyChart` · `Sparkline` · `LiveFeed` (SSE) · `GuestRow` · `OfferCard` · `OfferConstructor` · `PhonePreview` · `StaffLeaderboard` · `RewardCalculator` · `QRKitPreview` · `LevelLadder` · `AdviceCard`.

### Правила для графиков

Взяты из проверенной методики, нарушать не надо:

1. Форму выбирает задача данных, а не вкус. Одно число — плитка, не график.
2. Легенда обязательна при двух и более сериях. Одна серия — легенды нет, её называет заголовок.
3. Тултип по наведению — по умолчанию на всех графиках, кроме голой плитки.
4. Табличное представление доступно везде, где есть график, — кнопка «Таблицей».
5. Сетка и оси приглушённые, метки в текстовых токенах.
6. Никаких двух осей Y. Две разномасштабные величины — два графика.
7. Скруглённые концы столбцов 4px, зазор 2px между сегментами стека.

## 7. Тексты интерфейса

Правила важнее компонентов: продукт для владельца кафе, а не для аналитика.

- Никакого жаргона. Не «RFM-сегмент», а «постоянные». Не «churn», а «перестали приходить». Не «redemption rate», а «сколько потратили из начисленного».
- Числа с пояснением, что они означают для бизнеса. «12 400 ฿» — плохо. «12 400 ฿ — я должен гостям баллами, это обязательство, а не расход» — хорошо.
- Пустые состояния объясняют, что сделать, а не констатируют пустоту.
- Ошибки говорят, что делать дальше. «Ошибка 409» — плохо. «Гость только что потратил баллы в другом месте. Нажмите пересчитать» — хорошо.
- Кнопка называет действие, а не абстракцию: «Отправить 31 гостю», а не «Отправить».
- Числа в кнопках и заголовках всегда конкретные, подставленные из данных.

**Локализация.** Четыре языка, все строки в JSON, ключи по смыслу (`dashboard.liability.label`), не по тексту. Плюрализация через ICU MessageFormat: в русском три формы, в тайском одна.

## 8. Доступность

- Контраст текста к фону минимум 4,5:1, крупного — 3:1. Проверяется в CI линтером.
- Все интерактивные элементы достижимы с клавиатуры, порядок табуляции осмысленный, фокус видимый.
- Цель нажатия минимум 44×44 на мобильных.
- Формы: каждый input связан с label, ошибка привязана через `aria-describedby`.
- Модалки и шторки: ловушка фокуса, закрытие по Esc, возврат фокуса на инициатор.
- Живая лента — `aria-live="polite"`, иначе скринридер зачитает каждое начисление.
- Смысл никогда не передаётся одним цветом: у статуса есть иконка или подпись.

---

## 9. Что не делаем

Не тянем UI-библиотеку целиком. Radix-примитивы для доступности сложных компонентов (диалог, меню, тултип) плюс свои стили — да. Material UI, Ant Design и Chakra — нет: их визуальный язык перебьёт наш, а перебивать его обратно дороже, чем написать двадцать компонентов.

Не используем Tailwind как замену дизайн-системе. Если Tailwind — то только с токенами из `tokens.css`, прокинутыми в конфиг, и с запретом произвольных значений вроде `bg-[#1a2b3c]` (правило линтера).
