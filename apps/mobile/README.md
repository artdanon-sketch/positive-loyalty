# Мобильные приложения

Три приложения для Android: **Владелец**, **Касса**, **Карта гостя**.

## Что это и чем не является

Это **оболочки**, а не отдельные приложения. Исходники живут во фронтах:

| Приложение | Идентификатор | Исходник | Что показывает |
|---|---|---|---|
| POSitive Владелец | `app.positive.loyalty.owner` | `apps/admin` | Бэк-офис целиком: обзор, операции, гости, касса |
| POSitive Касса | `app.positive.loyalty.cashier` | `apps/admin` | Только экран кассы |
| POSitive Карта | `app.positive.loyalty.guest` | `apps/guest` | Карта гостя: баллы и код для кассы |

Владелец и кассир собираются **из одного исходника**. `docs/03`, раздел 10 прямо против третьего фронта: «бэк-офис адаптивный», кассир видит то же приложение с ролью `CASHIER`. Здесь ничего этому не противоречит — код общий, различается только упаковка.

Зачем тогда два приложения, а не одно? Иконка на телефоне обещает конкретную вещь. Приложение с названием «Касса», открывающее отчёты по выручке, — сломанное обещание, даже если человек имеет право эти отчёты видеть.

**Это не защита.** Права живут на сервере: `AdminController` закрыт для роли `CASHIER`, и по прямой ссылке кассир получит отказ независимо от того, какое приложение установлено.

## Адрес сервера настраивается в приложении

В браузере на ноутбуке `localhost:3000` — это тот же ноутбук, и всё сходится. В приложении на телефоне `localhost` — это сам телефон, и API там нет.

Поэтому адрес хранится на устройстве и меняется на экране входа: «Адрес сервера» под кнопкой. Указывать нужно адрес компьютера, где запущен API, в той же сети Wi-Fi — например `http://192.168.1.10:3000/v1`.

Зашивать адрес при сборке нельзя: у каждого заведения он свой и меняется вместе с переездом.

## Сборка

APK собираются **в CI**, а не локально: нужны JDK, Android SDK и Gradle — около полутора гигабайт установки плюс принятие лицензий SDK. На раннере GitHub всё это уже есть.

```
Actions → Android → Run workflow
```

Три APK приезжают артефактами запуска. Подпись отладочная: такой APK ставится при включённой установке из неизвестных источников и не годится для магазина.

### Локально, если Android SDK всё-таки стоит

```bash
pnpm --filter @positive/mobile-cashier run prepare:android
cd apps/mobile/cashier/android && ./gradlew assembleDebug
```

`prepare:android` делает три шага: собирает веб-часть в нужном режиме, копирует её в `www/`, синхронизирует с нативным проектом.

## Что отслеживается в репозитории

`android/` — **да**: там наши разрешения и настройки, которые потеряются при пересоздании. Камера для сканера QR объявлена в манифесте владельца и кассира; гостю она не нужна, он свой код показывает, а не сканирует.

`www/` и `dist-*` — **нет**: это результат сборки.
